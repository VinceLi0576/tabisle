# 新浏览器接入与重复收藏

## 为什么要改

用户接入新浏览器，是为了开始使用现有资料。
首次同步不应强迫用户理解“本地版本”和“云端版本”，再逐条裁决历史收藏。
同一个网址收藏在不同文件夹里，也可能是有意安排。

## 产品流程

首次接入时先保存原始备份，再把新浏览器原有资料整批收纳，保留子目录。
现有主资料继续作为日常使用入口。

```text
收藏夹栏
├ 主资料各分组
└ 待整理
   ├ Edge 待整理（设备名称）
   │  └ 该浏览器原有目录与收藏
   └ Chrome 待整理（设备名称）
```

待整理区域放在末尾，默认折叠。
用户可以自行改名、移动和整理；显示名不能作为同步身份。
新浏览器原来没有收藏时，不创建空的待整理来源文件夹。

首次接入只展示总数和收纳位置，不做跨来源的网址身份匹配。
相同网址暂时并存，日后在详情栏处理。

## 已完成代码与尚未完成的边界

本轮代码提供冲突批量选择、网址打开入口，以及详情中的重复收藏清单。
重复清单按完整 URL 精确比较，包含查询参数和锚点。
展示每份名称和目录路径，提供打开网页、查看该份详情、删除其他副本和撤销。
当前正在编辑的一份从原有删除入口处理。

删除重复副本前保存保护备份；共享备注不随副本删除。
撤销恢复原名称、网址、父文件夹和位置；原文件夹已不存在时提示使用保护备份，不猜测目标位置。

首次整批接入的持久化流程仍是以下设计，不能当成已完成的产品功能。
同步事件诊断已加入，但浏览器兼容性根因仍需要实际采集事件证据。

## 导入批次与失败恢复设计

导入批次包含随机批次标识、来源设备标识、来源快照指纹、目标目录 UUID、阶段和完成时间。
本机与云端都需保存批次记录；更新云端时继续使用版本条件写入，不能另建无锁状态覆盖。

阶段依次为：准备保护副本、创建候选树、云端写入、本机应用、读回核验完成。
只有本机和云端都核验一致，才能记录完成。

重试按批次和目录 UUID 续做，不凭同名文件夹决定，不重复给整棵树套目录。
已有共同基线时跳过首次收纳，继续按 UUID 三方合并。
重装导致身份丢失时，不能把本机所有现有内容默认认定为新的来源资料。
先核对云端批次、节点身份及原始快照；证据不足时保留保护副本并提供一次明确的来源选择。

已有半完成的同步现场必须走恢复迁移，不走空白新设备流程。
对比原始备份、当前云端和当前本机，结合身份映射、路径与网址核对。
UUID 变化不等于收藏丢失；不能仅靠集合差就移动或删除内容。

----------------

## 重复收藏与同步冲突是两回事

重复收藏是多个独立记录使用同一网址，可以全部保留。
同步冲突是同一个记录被两边改成不同内容，需要决定该字段最终内容。

首次收纳绕开跨来源的 URL 身份匹配。
后续正常同步仍需处理真正的同记录并发修改，不能因增加待整理目录而删除并发保护。

备注当前采用归一化网址作为共享键，与精确重复清单的范围不同。
仅锚点不同的两份记录可能共享备注，但不会列为完全相同网址。
界面应写明共享范围，不展示虚假的“每份独立备注差异”。

----------------

## 发布前验收

- 空的新浏览器收到主资料，不生成空归档。
- 有收藏的新浏览器整批收纳，主资料顺序不被改乱。
- 同网址不同路径、不同名称均保留，首次收纳没有逐条冲突选择。
- 断网、关闭浏览器、云端版本竞争和本机应用中断后，可继续同一批次。
- 重装、目录改名和设备改名不会重复导入同一份资料。
- 删除一份收藏保留其他副本与备注；撤销恢复原位置。
- URL 参数和锚点不同不自动判定为重复，更不自动删除。
- Chrome 与 Edge 的原生事件、内部页面网址转换经过独立测试。
- 本机应用和云端读回均通过，才显示同步成功。
- 浏览器账号同步与插件同步分别说明；不能伪造或猜测账号同步开关。

研究方案可公开；真实收藏、账号、应用密码、个人设备记录不进入公开仓库。
