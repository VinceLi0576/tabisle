# 备份与同步的选择

核对日期：2026-09-13。

真实 WebDAV 测试已确认上传、读取、删除和完整备份下载核对可用，云端月份列表正常。

坚果云返回未加引号的版本标识，且 PUT 的 If-None-Match 未阻止覆盖。
当前适配使用服务器原样返回的标识进行 If-Match 写入；首次创建改用暂存文件与 MOVE / Overwrite:F。
关闭请求缓存后，正确版本写入通过，错误或过期版本返回 412；目标已存在时 MOVE 返回 409，并保留目标内容。
这些能力已在不含个人资料的独立测试文件中验证，测试文件已清理。

能力验证不等于已运行多设备同步。首次确认合并和开启自动同步仍由用户操作。

## 为什么保留两种能力

同步让设备趋于相同，也会传播误删。
备份则保留过去的状态，让误操作有机会撤回。

推荐把坚果云作为云端存放位置，由书签首页直接完成双向同步，并独立保留历史快照。
不需要安装 floccus 或其他同步插件。
不需要自建服务器，也不需要 GitHub Token。

## 三个方案

| 方案 | 书签首页自动备份 | 云端上传 | 外部同步 |
| --- | --- | --- | --- |
| 坚果云 WebDAV | 可按每小时、3 小时、每天、7 天或 30 天保存 | 验证连接后开启 | 浏览器账号同步可按需保留 |
| 浏览器账号同步 | 可保留本机备份 | 关闭 | 自行在 Chrome / Edge 开启 |
| 纯本地 | 关闭 | 关闭 | 自行关闭浏览器书签同步并暂停其他同步工具 |

纯本地保留书签和备注，不自动删除已有备份。
手动导出不会新增历史；手动备份和恢复前保护会保存本机副本。

书签首页不能读取或切换浏览器账号同步状态，也不能替用户控制其他同步扩展。
页面提供浏览器设置入口和操作提示，实际状态以对应软件为准。

## 配置坚果云

在 [坚果云官网](https://www.jianguoyun.com/)注册或登录。
应用密码的获取和管理方式以坚果云官网为准，书签首页页面不重复维护其菜单步骤。

在书签首页填写账号邮箱、应用密码和备份目录：

```text
https://dav.jianguoyun.com/dav/TabIsle/backups/
```

这是默认的完整快照目录。已有用户的自定义目录继续保留。

点击「验证连接并启用云备份」，授权扩展访问坚果云。
程序建立目录并检查连接，成功后才保存新连接并启用上传；失败会保留此前的连接配置。

验证会创建目录，但不会上传书签。
之后的手动备份、定时备份会上传；已经过期的定时任务可能在下一次后台检查时执行。

新快照按月份存放：

```text
TabIsle/backups/2026-09/bookmarks-时间-唯一标识.json
```

文件名不同，不覆盖旧文件。
上传结果不确定时，重试先读取同名文件，按实际 JSON 数据核对，不受字段排列顺序影响。
相同内容跳过重复上传，内容不同时停止；独立快照使用唯一文件名。
云端不可用时仍保存到本机；后台检查时重试最新待上传的副本。

云端历史可切换月份，也能读取旧版本直接放在根目录的快照。
不自动删除云端快照；只使用自己的同步文件，不读取其他工具的同步文件、临时文件和锁文件。

### 免费额度如何计算

官方价格页列出免费版每月上传 1 GB、下载 3 GB，并非每月 5 GB。
5 GB 出现在单文件大小的介绍中，不能当作免费月流量。
实际权益以账号页面和官方最新说明为准。

WebDAV 官方说明还有免费版每 30 分钟 600 次请求、每次列目录最多 750 项等限制。
因此快照按月存放；达到目录条目限制时，页面提示到坚果云网页核对，不能假定已读到全部历史。

坚果云自己的文件历史版本与书签首页快照是两套机制。
官方历史版本帮助页说明免费版一个月、付费个人版三个月；价格页展示可能随方案调整，不依赖它作为本产品的恢复保证。
没有找到可通过公开 WebDAV 接口读取其内置历史版本的官方说明。

来源：[价格与权益](https://www.jianguoyun.com/s/pricing)、[WebDAV 官方说明](https://help.jianguoyun.com/?p=2064)、[文件历史版本](https://help.jianguoyun.com/?p=190)。

## 书签首页直接同步多个浏览器

每台浏览器都安装书签首页，连接相同坚果云账号和备份目录，设备名称默认自动生成，也可自行修改。
点击「验证并预览同步」，检查变化与冲突，再确认同步。
完成首次同步后，可选择每 15 分钟自动同步；浏览器关闭时不能执行。

首次连接保留双方内容。后续以最近一次成功同步的文档为共同基线，分别比较本机和云端的变化。
不同字段的修改可以合并，同字段同时修改、删除对修改、疑似旧内容回流会暂停等待选择。
删除比例超过 20% 时，也会停止自动应用，要求手动预览。

书签使用独立 UUID，不把 Chrome / Edge 的本机 ID 当作跨设备身份。
已有身份优先；身份重建时尝试按路径、网址一对一对齐，不把多份同网址书签简单压成一份。
浏览器账号同步带来的新增会参与对齐。疑似删除后回流与用户重新收藏无法可靠区分时，留给用户确认。

同步包括书签、文件夹、顺序、备注名、说明、图标、标签和分组颜色。
布局和折叠偏好仍由各设备保留；完整备份与恢复可以迁移这些偏好。

Chrome / Edge 自带账号同步可以保留，书签首页不会强制关闭。
这不代表任何同步组合都绝不会冲突：浏览器书签 API 不提供整树事务，检测到同时修改会停止并保留保护版本。

### 云端并发保护

同步文档放在所配置目录的子目录中：

```text
sync/state.json
```

这个文件表示当前共同版本，历史快照继续按月份独立存放。

首次验证会建立不含个人数据的临时文件，检查创建时禁止覆盖、正确和过期的版本条件写入，再清理测试文件。
验证失败不会启用双向同步，独立云备份仍可使用。

已有同步文件必须通过 If-Match 写入，使用服务器原样返回的版本标识。
新文件先上传到唯一暂存路径，再用 MOVE / Overwrite:F 创建共享文件，最后清理暂存文件。
目标抢先被创建时，409 / 412 结合目标存在性检查视为并发冲突；旧版本写入返回 412 时，本次不覆盖，要求重新预览。
所有同步请求禁用缓存，避免把过期版本标识用于写入。

同步前保留本机保护版本；改写已有云端版本前，也保留一份云端旧内容的快照。
持久化未完成标记并逐条保存本机身份映射，减少中断后重复创建的风险。
中断后自动同步停止，再次手动预览按首次合并处理，保留双方数据，不把半成品解释为删除。

测试覆盖两端合并、字段冲突、删除冲突、ID 重建、条件写入竞争、响应丢失、并发新增和恢复继续。
真实坚果云底层能力验证已通过，见文档开头；不将其扩大为实际多设备同步已经完成。

## 恢复顺序

1. 检查当前同步状态，可暂时关闭浏览器账号同步，减少恢复期间的外部变化。
2. 从本机、云端月份或导入 JSON 选择版本。
3. 查看新增、删除、改名、改地址、移动、排序及附属数据变化。
4. 确认恢复；程序先保存一份当前完整状态，再修改书签栏。
5. 检查书签与备注；书签首页自动同步已暂停，先预览合并或选择冲突处理，再决定重新开启。

恢复尽量复用现有书签，保留其创建时间。
已被删除、必须重建的书签会得到新的浏览器创建时间。
预览后数据有变化，会要求重新预览；恢复中断则保留保护副本与未完成提示。

新快照携带按内部身份记录的文件夹折叠状态，跨设备恢复后映射到新的浏览器标识。
旧快照仍可导入；未包含折叠状态时，不覆盖当前折叠偏好。

本机最多 20 份，按约 6 MB 的存储预算优先清理旧版。
浏览器关闭时任务不运行，重新启动或打开首页后检查补做；不是保证固定时刻准点执行。

来源：[Chrome 定时任务文档](https://developer.chrome.com/docs/extensions/reference/api/alarms)。

## 以后存数据库是否可行

WebDAV 可以存放 JSON、附件和数据库导出文件。
它不是数据库服务，不负责记录合并、冲突解决、事务或实时订阅。

以后可复用此存储通道，但数据库同步协议、增量策略和额度消耗需要单独设计。
不能保证任意数据量、任意设备数都免费。

## Chrome 账号同步的入口与首次连接

```text
chrome://settings/syncSetup/advanced
```

在 Chrome 地址栏打开此地址，进入「管理您的同步数据」。
书签首页备份页的「管理浏览器的书签同步」按钮也直达这里。

若只想停用 Google 书签同步，先选「自定义同步」，再关闭「书签」。
无需关闭其他数据项目；书签首页不会代替用户切换 Google 同步开关，也不会根据自己的备份方案推断这个开关的状态。

首次 WebDAV 同步按以下规则生成预览，确认后才执行：

| 共享同步资料 | 本机资料 | 结果 |
| --- | --- | --- |
| 没有 | 有 | 上传本机作为同步起点 |
| 有 | 空 | 将云端资料加入本机 |
| 有 | 有 | 保留双方，匹配相同条目，有冲突先选择 |

云端历史快照与共享同步资料分别保存。
即便已经上传过完整备份，仍需在资料来源设备完成首次同步，才能让其他设备从共享同步资料合并。
下载快照只保存文件；恢复需单独预览并确认，会传播到已启用 Google 书签同步的设备。

Google 书签同步与书签首页 WebDAV 同步可以同时开启。
新增测试模拟 Google 先交付文件夹和书签、WebDAV 后交付相同资料与备注，确认匹配后不重复、不反复上传。
另模拟已删除书签经外部同步重新出现，确认自动同步暂停，等待用户判断是否保留。
这些测试使用模拟书签 API 与 WebDAV，不能当作真实 Google 云服务与坚果云长期同时运行的验证。

书签首页的自动同步需先完成一次手动合并，再勾选「每 15 分钟自动同步」。
运行依赖浏览器开启；冲突、大量删除、疑似回流或同步中断时暂停，回到预览页处理。

## 多台电脑应共用什么配置

同一套同步资料使用同一个坚果云账号、同一个完整目录地址。
第二台电脑直接复制第一台配置的目录，包括地址最后的文件夹路径。
不要按设备名称另建目录，否则会形成彼此独立的同步资料。

设备名称只是写在备份中的来源备注，不参与同步地址或书签身份匹配。
可以叫「笔记本 Chrome」「台式机 Chrome」「测试 Chrome」。
同名也能同步，只是查看历史时难以辨认来源；并不强制每台设备使用不同名称。

应用密码用于验证同一个坚果云账号。
可沿用同一应用密码，或使用该账号另建的有效应用密码；它不决定同步资料的分组。

每台浏览器独立保存账号配置、设备名称、备份频率和自动同步开关。
即使两台浏览器加载同一个代码目录，这些设置也不会自动复制。

先在资料最完整的浏览器完成首次同步，再连接后续电脑。
每台都要检查首次预览并确认，之后分别启用自动同步。
如果只想留备份，验证连接后使用「立即备份」即可，不需要执行双向合并。

## 自动设备名与改名

每个浏览器安装首次使用备份功能时，生成自然词语组成的随机名称，例如「晨光·松林·白鹭」。
不附加日期或数字尾巴；以后打开页面沿用保存的名字。
已有自定义名称保留，旧的空名称或「未命名设备」会自动补齐。

用户可以修改名称并保存。留空保存时保留当前名字。
从 A 改成 A1 后，本机设置和未来新建的备份使用 A1，旧备份继续显示当时的 A。
上传旧备份不会修改它的来源名，恢复旧版本也不会改变本机当前设备名。

改名不会改变坚果云账号、目录、共同同步版本或自动同步开关，也不会新建书签或触发整库上传。
每个安装同时生成并持久保存独立的设备标识，新快照携带该标识，改名时保持不变。
随机显示名称不保证全球唯一；同名不会成为合并设备或同步书签的依据。

## 账号看起来为空时如何判断

连接成功后，账号和应用密码保存在当前浏览器的扩展存储中。
密码框不会回填明文，页面会明确显示「应用密码已保存，无需重新填写」。
密码框留空时，验证会使用保存的密码；只有更换账号或密码时才需重新填写。

每次打开本页优先展示坚果云配置，实际备份与上传开关仍按保存的方案执行。
如果之前关闭过云备份，仅打开页面不会替用户重新开启上传。

开发更新可能使旧页面与扩展后台的连接失效。
出现重新加载提示时，先保留未保存的输入，再刷新页面读取配置；不能把页面连接失败直接当成账号已被删除。
普通 Chrome 与测试 Chrome 的账号存储彼此独立。

## 每台设备的倒计时

自动备份、持续同步、失败重试分别保留本机计划时间，不随备份或跨设备同步复制。
每轮在原周期后随机延后 30 秒到 5 分钟，页面显示倒计时和计划时间；重开页面不重新起算。
休眠错过计划后先错峰再补做一次。随机错峰减少同时请求，云端版本检查继续防止并发覆盖。
